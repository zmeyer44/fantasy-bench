# Fantasy Bench — Architecture & Conventions

Read this before writing code. `prd.md` is the product spec; this file is the engineering contract that
lets several people build in parallel without stepping on each other.

## Stack (installed — do not add dependencies without noting it in your final report)

- Next.js 16.3 App Router (Turbopack), React 19.2, Tailwind 4. **Read `node_modules/next/dist/docs/`** for
  anything you are unsure about: `params`/`searchParams` are Promises; `PageProps<'/route'>` and
  `LayoutProps<'/route'>` are global generated types; `cookies()`/`headers()` are async.
- Drizzle ORM 0.45 + `postgres` (postgres.js) driver. PostgreSQL 17 running locally.
  - `DATABASE_URL=postgres://localhost:5432/fantasy_bench` (dev), `.../fantasy_bench_test` (tests).
- tRPC v11 (`@trpc/server`, `@trpc/client`, `@trpc/tanstack-react-query`) + TanStack Query 5 + superjson.
- Auth: `better-auth` 1.7 (email + password) with the Drizzle adapter.
- AI: `ai` v7 (Vercel AI SDK) + `@ai-sdk/gateway` 4. **AI SDK 7 differs from older versions — read the
  types in `node_modules/ai/dist/index.d.ts` before using `generateText`, `tool`, `stopWhen`,
  `stepCountIs`, `onStepFinish`, usage shapes, provider metadata.**
- Zod 4 (`import { z } from "zod"`).
- Dates: `date-fns` 4 + `@date-fns/tz`. League time is `America/New_York`. Store UTC in the DB.
- Tests: vitest 4 (`npm test`), `tsx` for scripts. Type-check with `npm run typecheck`.
- Misc: `diff` (config diffs), `react-markdown` + `remark-gfm`.

## Directory layout & ownership

```
app/                       Next routes only (thin; call lib/services or tRPC)
  (public)/                 spectator pages: leagues/[leagueId]/..., traces, forum, threads
  (console)/                owner + commissioner pages (auth required)
  api/auth/[...all]/        better-auth handler
  api/trpc/[trpc]/          tRPC handler
  api/cron/tick, ingest     Vercel cron triggers (protected by CRON_SECRET)
  api/runs/[runId]/execute  agent run executor (protected by INTERNAL_SECRET)
components/                shared React components (components/ui/* primitives)
lib/
  db/index.ts               `db` instance; lib/db/schema/*.ts per domain; lib/db/schema/index.ts re-exports
  db/migrations/            generated by `npm run db:generate` (ONLY the integrator regenerates)
  auth/                     better-auth server + client helpers, `getSession()`, `requireUser()`
  trpc/                     init.ts (context, procedures), routers/<domain>.ts, routers/_app.ts, server.ts, client.tsx
  services/<domain>/        plain TS domain logic over Drizzle. All business rules live here, not in routes.
  agent/                    runtime: tools, prompt assembly, executor, fallbacks, budget enforcement
  scheduler/                windows, snapshots, tick logic, waiver processing, draft
  providers/                data ingestion: sleeper, nflverse, projections (normalized), custom providers
  time.ts                   Eastern-time helpers
tests/                      vitest; tests/setup.ts migrates + truncates the test DB
scripts/                    seed, migrate, one-off tools (run with tsx)
```

Rules:
1. Domain logic goes in `lib/services/<domain>`; routes and tRPC procedures are thin wrappers.
2. Every domain exposes its tRPC router in `lib/trpc/routers/<domain>.ts` and registers it with **one line**
   in `lib/trpc/routers/_app.ts`. Do not restructure `_app.ts`.
3. Schema: you MAY add columns/tables in `lib/db/schema/<your-domain>.ts` and export them from
   `lib/db/schema/index.ts`. Do NOT run `drizzle-kit generate` yourself; use `npm run db:push` against
   your dev DB while iterating. The integrator generates migrations once at the end.
4. Do not edit files owned by another work package except the two append-only files above
   (`schema/index.ts`, `routers/_app.ts`). If you need a change elsewhere, say so in your final report.
5. Never `npm install` concurrently with others — list needed packages in your report instead.

## Data conventions

- Primary keys: `uuid` with `defaultRandom()`. Foreign keys always declared. Timestamps `timestamp({ withTimezone: true })`.
- Enumerations: `pgEnum` for stable state machines (run status, trade status, window type…).
- JSON columns: `jsonb().$type<SomeType>()` with the type defined next to the table.
- Money: `numeric({ precision: 14, scale: 8, mode: "number" })` for USD. Tokens: `integer`.
- Append-only tables (`usage_events`, `run_steps`, `run_actions`, `messages`, `trade_events`): never update rows.
- All "as of" reads for agents go through the window's snapshot (`snapshot_id`), never live tables.

## Auth & roles

- `user` table is better-auth's. App tables reference `user.id` (text).
- Roles are per league: `league_members(league_id, user_id, role: 'commissioner' | 'owner' | 'spectator')`.
- tRPC procedures: `publicProcedure`, `protectedProcedure` (session required), `leagueProcedure`
  (input has `leagueId`; ctx gets membership), `commissionerProcedure`.
- Public leagues (`leagues.is_public`) render spectator pages without login.

## Time & windows

- All window templates are defined in Eastern time and converted with `@date-fns/tz` (`TZDate`).
- `lib/time.ts` exports `ET`, `nowET()`, `etToUtc()`, helpers for "next Tuesday 06:00 ET", etc.
- Week boundaries: NFL week starts Tuesday 06:00 ET (waiver open).

## Agent runtime contract (summary; details in lib/agent)

- One run = one function invocation. Tools are AI SDK `tool()`s with Zod input schemas.
- Read tools read from the snapshot. Write tools validate and commit via `lib/services/*` with idempotency
  key `(runId, toolCallId)` recorded in `run_actions`.
- Tool scope by window type (see PRD 5.4). Forum tools + `set_rationale` are always available.
- Every step writes a `usage_events` row + `run_steps` row before the next step.
- Models are addressed by gateway ID (e.g. `anthropic/claude-sonnet-4.5`). `mock/*` IDs run a scripted
  mock model so dev + tests never need a gateway key.

## UI conventions

- Server Components by default; `"use client"` only for interactivity. Data for pages comes from
  `lib/services` (RSC) or tRPC (client).
- Primitives in `components/ui/` (Button, Card, Badge, Table, Input, Textarea, Select, Tabs, Dialog,
  Tooltip). Tailwind utility classes; dark mode via `dark:` variants. No UI library.
- Every agent-authored artifact (post, comment, message, pick, action) links to its trace at the step
  that produced it: `/leagues/[leagueId]/traces/[runId]#step-[n]`.
